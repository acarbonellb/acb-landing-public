# Design System sync

The Design System artifact (its URL is `artifact` in [`sources.json`](sources.json)) is a **derived copy** of this repo: tokens, fonts, the site icon, and the site's real components compiled for React 19 with live previews and the real data. The repo is the source of truth; the artifact changes only by a re-sync from a commit on `main`.

`sources.json` lists every repo file the artifact is built from, by part: `tokens` (`globals.css`, `layout.tsx`), `assets`, `mirrored` (`page.tsx`, which `scripts/entry.tsx` copies by hand as `Page`), `content` (the copy and eval results the previews show: they change no design), `bundle` (every other file the component bundle reads, written by the build) and `skill` (this skill's scripts that shape the bundle, the cards and the tokens, the token notes, and the hand-written copy in its `project/` folder).

The hand-written copy lives in this skill's [`project/`](project) folder, at the paths the artifact uses: every component's `components/<Name>/README.md`, the project `README.md`, `assets/*/README.md` and the cover card `components/Cover/preview.html`. Edit it there and review it in a pull request; `build.mjs` writes it into the `<project dir>`, so never edit it on the artifact.

## Steps

1. **Find what is stale.** Read `project/tokens.json` from the artifact (`Artifact` read with `path`) and take `meta.ref` (`main@<sha>`). Run `git diff --name-only <sha> origin/main` and match the files against `sources.json`; a `skill` file counts as `bundle` (a component, card or README changed in this skill reaches the artifact only by a sync). Done when you have the set of parts to redo, or none, in which case report the artifact current and stop. When only `content` changed, the artifact's design is current and only its copy lags: say so and sync only if the user wants it (any other sync carries the content along, since the build always reads the current files).
2. **Check out the commit you sync to**: `origin/main`, with `pnpm install --frozen-lockfile` if `node_modules` is missing. Done when `git status` is clean at that commit.
3. **Read before you write.** First `read` the artifact URL with no `path`: the publish is refused until that read has seen the live version, and a read by `path` doesn't count. Then `read` the type's `SKILL.md` (file shapes, the publish call, the index rules), `project/design-system.json`, `project/tokens.json` and every `project/components/` file a `scope: "files"` listing shows, in one call with `paths`. They land under one folder in your scratchpad: that folder's `project/` is the `<project dir>` below. Done when it holds every `project/components/` file of the listing, plus `project/README.md` and `project/assets/*/README.md`: `build.mjs` lists what to publish against them.
4. **Redo each stale part**:
   - **tokens**: nothing by hand. `build.mjs` writes the whole `tokens.json`: every value from `globals.css` (compiled by the site's Tailwind) and `layout.tsx`, every usage note and name from [`token-notes.json`](token-notes.json). It fails, naming the token, on a value it can't parse, a token with no note or a note with no token: write or remove the note in `token-notes.json` (a new colour's note comes from the code that uses it; remove a token only with the user's go-ahead), and the change goes in a PR.
   - **mirrored**: make `Page` in `scripts/entry.tsx` compose the page exactly as the new `src/app/page.tsx` does.
   - **bundle** (and after **tokens**, **mirrored** or **skill**, `token-notes.json` included): `node .claude/skills/design-system-sync/scripts/build.mjs <project dir>`. It also writes this skill's `project/` folder (the READMEs and the cover card) into the `<project dir>`. If it fails because the bundle reads a file `sources.json` doesn't list, rerun with `--update-sources`; the changed `sources.json` goes in a PR.
   - **assets**: upload a changed icon as an asset and update its record in the index; copy a changed font file to `fonts/`.
   - **a component added or removed**: its entry in `components` in `scripts/entry.tsx`, its card in `scripts/previews.mjs`, its `project/components/<Name>/README.md` in this skill (listed in `sources.json` `skill`), its props in `components/index.d.ts` and its source in `tokens.json` `meta.components`, all in step.
   Done when every stale part is rebuilt.
5. **Check**: `node .claude/skills/design-system-sync/scripts/check.mjs <project dir> <shots dir> Page`. It first fails on a component out of step (the step-4 pieces, or leftovers of one removed) or on an `AgentStatus` in `index.d.ts` that differs from `agentStatuses` in `profile.ts` (that file is hand-written: fix it there), then renders every preview; look at `Page.<theme>.png` in both themes. Done when it prints that every component is complete and every preview renders, and the page looks like the live site.
6. **Publish**: publish to the artifact URL in one call exactly the files `build.mjs` listed under `publish:`, plus every file you edited by hand (`components/index.d.ts` with `contentType: "text/plain"`), and `null` for each file `check.mjs` reported as left over. The `publish:` list carries `tokens.json` (its `meta.ref` and `meta.synced` are the checked-out commit's) and the READMEs and the cover card the build changed. The index goes last, read again right before (only the index), carrying a new `lastChange`. Done when the publish succeeds and `git status` shows nothing but the `sources.json`, `entry.tsx` or `previews.mjs` changes you meant.

## Reference

- **Colours live only in `tokens.json`.** `build.mjs` compiles `globals.css` without its two theme blocks, so the artifact's `tokens.css` supplies every colour and an edit on its page would win. Edits belong in the repo (values in `globals.css`, notes in `token-notes.json`); a token changed on the page is overwritten by the next sync.
- **How `tokens.mjs` reads each token**: colours from the theme blocks, shadows from the `globals.css` rules that set `box-shadow` (named by class), `space-<n>` and `radius-<x>` from Tailwind's `p-<n>` and `rounded-<x>`, containers and type styles from the classes their note names, families from `@theme`'s `--font-<key>` through the next/font loader in `layout.tsx` (or the note's font file) followed by the note's fallback stack. A fluid size shows its largest value; `rounded-full` shows as `9999px`.
- **The scripts write only outside the repo**: `build.mjs` refuses a `<project dir>` inside it.
- **The bundle runs on the page's React.** `build.mjs` resolves `react` and `react/jsx-runtime` to `window.React`, with a ref-based `useEffectEvent` when the page's React lacks it, so the same `bundle.js` mounts on the artifact's React 19 and on a Design canvas, whose runtime provides React 18. Bundling React 19's own JSX runtime breaks the canvas (minified React error #31). A new React 19-only API in a component needs the same fallback there.
- **The agent is unreachable from the artifact.** `entry.tsx` gives the chat `agent.invalid` endpoints, so `Agent` and `Contact` render as on the site and a question sent from a preview fails. The MCP URL shown is the site's public one.
- **The edit hook** (`scripts/hook.mjs`, wired in `.claude/settings.json`) reminds once per session, on file-tool edits to listed paths outside `content`. Shell edits and changes made outside Claude Code reach the artifact only through step 1.
